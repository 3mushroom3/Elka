# Развёртывание на VPS

Эта инструкция ещё не проверялась на настоящем сервере: сборка приложения проверена локально,
а Docker-образ и связка контейнеров запускаются впервые. Первый запуск лучше делать вместе
с разработчиком.

## Что нужно

- VPS в России с Ubuntu 22.04 или 24.04, от 2 ГБ памяти и 20 ГБ диска.
- Домен (или поддомен), A-запись которого указывает на IP сервера. Без домена не будет HTTPS,
  а без HTTPS не работает вход и камера на телефонах.
- Открытые порты 80 и 443.

## Первый запуск

```
# 1. Docker
curl -fsSL https://get.docker.com | sh

# 2. Код проекта
git clone <адрес репозитория> elka && cd elka

# 3. Настройки
cp .env.production.example .env
nano .env        # заполнить DOMAIN, пароли, ADMIN_PASSWORD

# 4. Сборка и запуск
docker compose up -d --build
docker compose logs -f app    # дождаться строки "Ready"
```

После этого сайт открывается по адресу `https://<DOMAIN>`. Вход: логин и пароль из `.env`
(`ADMIN_LOGIN`, `ADMIN_PASSWORD`). Сертификат HTTPS Caddy получает сам, это занимает до минуты.

Что происходит при запуске контейнера приложения: применяются миграции базы, создаются аккаунт
менеджера и справочник видов товара (только если их ещё нет), стартует сайт.

## Обновление

```
git pull
docker compose up -d --build
```

Данные при этом сохраняются: база, фото и сертификаты лежат в томах Docker.

## Резервные копии

- **База.** Контейнер `backup` раз в сутки кладёт копию в папку `backups/` рядом с проектом
  и хранит 14 дней. Копии стоит забирать с сервера, например раз в день через `scp` или `rsync`.
- **Фото списаний.** Лежат в томе `uploads`. Сохранить в архив:
  `docker run --rm -v elka_uploads:/data -v "$PWD/backups":/out alpine tar czf /out/uploads.tgz -C /data .`

Восстановление базы из копии:

```
docker compose stop app
gunzip -c backups/elka-ГГГГ-ММ-ДД-ЧЧММ.sql.gz | docker compose exec -T db psql -U postgres -d elka
docker compose start app
```

Восстанавливать нужно в пустую базу. Если в ней уже есть данные, сначала пересоздайте её:
`docker compose exec db psql -U postgres -c "DROP DATABASE elka" -c "CREATE DATABASE elka OWNER elka"`.

## Telegram

1. В Telegram напишите @BotFather, создайте бота командой `/newbot`, получите токен.
2. Впишите токен в `.env` (`TELEGRAM_BOT_TOKEN`) и выполните `docker compose up -d`.
3. Менеджер открывает бота, нажимает «Запустить», узнаёт свой числовой ID у @userinfobot
   и вводит его в системе: раздел «Уведомления».

Серверу нужен доступ к `api.telegram.org`. Если хостинг его блокирует, уведомления внутри
системы продолжат работать, а в Telegram приходить не будут.

## Безопасность

- Приложение подключается к базе под ролью `elka` без прав суперпользователя, поэтому запрет
  на изменение журнала движений нельзя отключить из приложения.
- Пароль менеджера из `.env` используется один раз. После первого входа смените его
  в разделе «Сотрудники».
- Файл `.env` и папка `backups/` содержат пароли и данные: не выкладывайте их в репозиторий.
